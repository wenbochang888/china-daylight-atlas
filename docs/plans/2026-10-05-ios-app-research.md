中国昼夜地图：iOS App 转化调研与实施方案

调研日期：2026-10-05。本文是方案，不表示已经创建、签名或提交 iOS App。技术建议根据本仓库当前代码及下文官方资料制定；发布对象、地区和开发者身份须以维护者实际选择为准。

**1．建议采用的路线**

保留 Vue 3、TypeScript、MapLibre GL JS、自定义昼夜着色器及 Astronomy Engine，通过 Capacitor 8 的 iOS 原生容器加载随安装包内置的网页资源。继续维护同一套 Web 核心，在平台适配层接入 iOS 生命周期、偏好存储、状态栏、外链及系统分享。

这条路线的产品目标是“可离线使用的昼夜与节气观测工具”。原生的是安装、签名、系统集成和发布流程；地图与主要界面仍由 WKWebView 渲染，不应把它描述成 SwiftUI 全原生界面。Capacitor 官方确认 iOS 使用 WKWebView，并提供 JavaScript 与原生代码的桥接能力。[Capacitor iOS](https://capacitorjs.com/docs/ios)

不需要先引入 Ionic UI，也不需要新增服务器、登录体系或地图 API Key。优先复用现有界面和模型，比在 SwiftUI、Flutter 或 React Native 中重做地图和交互更符合本项目的投入产出。

| 路线 | 对本项目的影响 | 建议 |
| --- | --- | --- |
| Capacitor + 内置 Vue 资源 | 可复用现有组件、天文计算和 WebGL；补充原生适配 | 首选，先做真机技术样机 |
| SwiftUI + 原生地图／绘制 | 需要重做界面、地图交互、遮罩渲染及平台集成；模型也需迁移或桥接 | 真机验证证明 WebView 无法满足要求，或未来原生功能成为核心时再评估 |
| Flutter／React Native | Vue 组件不能直接变成其原生组件；JS 领域代码可能部分复用，但需另行验证 | 当前没有明显迁移动机 |
| 自写 WKWebView 容器 | 同样保留 Web 渲染，但需要自行维护更多桥接、资源处理和生命周期代码 | 当前不如采用成熟容器直接 |
| PWA／添加到主屏幕 | 适合先体验网页；本仓库尚未实现完整离线 PWA | 如果最终只是自己使用，可作为更轻的替代路线；不等同于本方案的 App Store App |

以上是基于项目结构的工程判断，不是各框架通用的性能排名。

**3．默认技术与产品决策**

建议首版继续使用“中国昼夜地图”名称、简体中文界面，定位为科普观测工具；App Store 分类优先考虑教育，具体年龄分级按真实内容填写，不默认选择儿童专区。

技术上选择 Capacitor 8 稳定版本，core／cli／ios 保持匹配并锁定；原生依赖优先 Swift Package Manager。官方 v8 环境要求 Node.js 22+、Xcode 26+，并将 SPM 作为默认依赖管理方式。[环境要求](https://capacitorjs.com/docs/getting-started/environment-setup)

产品最低系统建议定为 iOS／iPadOS 17，减少老版本 WebKit 的适配面。这是本方案的覆盖范围建议：Capacitor 自身支持 iOS 15+，但框架最低版本不代表本应用全部 CSS、DOM、音频和地图能力已经在该版本通过。[框架支持范围](https://capacitorjs.com/docs/ios)

构建时选用符合提交要求的稳定版 Xcode。Apple 自 2026-04-28 起要求上传 App Store Connect 的 iOS／iPadOS App 使用 iOS／iPadOS 26 SDK 或更新版本构建。SDK 版本与用户最低系统版本是两个不同设置。[Apple 提交要求](https://developer.apple.com/news/?id=ueeok6yw)

设备优先级为 iPhone，复用现有宽屏布局支持 iPad；只有完成 iPad 真机和窗口尺寸验收后才把它作为通用 App 交付。首版建议免费、无广告、无账户、无定位、无推送，核心操作全部离线。商业模式将来变化时单独设计，不在转化阶段增加额外系统。

**4．首版范围与后续范围**

首版保留固定全国图、34 省级选择、北京时间、两年观测范围、当年 24 节气、共享时间轴、双日期对比、音乐开关与时间同步、主题、沉浸模式，以及图形和音乐失败的重试。

为使 App 具有完整使用体验，建议增加安装图标与启动画面、关于与数据说明、隐私政策入口、版本信息和原生分享。分享优先做“当前观测卡片”：日期、北京时间、所选地区代表点信息、昼长，以及经验证可正确生成的地图图像。即使地图图像导出尚未通过验收，文本分享也应能独立工作，但不能将文本回退宣称为图像分享已经完成。

本地收藏观测方案、桌面小组件、节气提醒、实时定位和 Apple Watch 先列为后续需求。它们都不是完成本次 iOS 转化的前提。

保留已有初始状态：真正冷启动为今天、00:00、暂停，不默认恢复上次观察进度。主题与音乐偏好可记忆；背景返回保留尚存页面状态并暂停。后台被系统终止后再次打开按冷启动处理，不暗中新增持久化会话恢复。

**5．应用结构与资源打包**

建议结构如下；新增名称是计划，不代表文件已经存在：

```text
src/domain/                 保留现有天文与播放计算
src/components/             复用 Vue 界面及地图
src/platform/               新增少量 iOS／Web 适配函数
capacitor.config.ts         App 标识与 webDir 配置
ios/                        Xcode 工程、原生资源、配置和隐私清单
scripts/prepare-ios-web.mjs  从构建结果准备 App 专用资源
dist/                       原有网站构建
dist-ios/                   App 专用网页资源，生成后不提交
```

Capacitor 的 `webDir` 指向 `dist-ios`。生产环境使用安装包内资源，不将 `server.url` 指向网站；官方将该配置用于 live reload，明确不建议生产使用。[配置说明](https://capacitorjs.com/docs/config)

本次读取文件实际字节数如下，MB 按十进制计算，不是磁盘块占用、gzip 下载大小或 IPA 安装大小：

| --- | ---: | ---: |
| 完整 `dist/` | 26,921,202 | 26.92 MB |
| `dist/maps/` | 17,577,629 | 17.58 MB |
| `dist/assets/` | 8,502,350 | 8.50 MB |

主页面已使用内置全国数据，`maps/` 中的重复数据及市县分片当前不被请求。最直接的做法是正常构建网站，再由脚本只把 index、assets、favicon 及 App 所需说明资源复制到 `dist-ios`，生成资源清单并检查入口和动态导入引用。这样可排除约 65% 的现有构建字节，且无需删除仓库数据或改变网站部署。

这不是删减全国几何；内置数据的完整海岛、边界及天文输入仍保留。原始快照、准备脚本和数据一致性校验继续留在仓库。

最终 IPA 下载大小和安装大小需由 Xcode Archive／App Store Connect 测量，不能拿 9.34 MB 作为承诺。音乐可后续评估压缩，但当前 5.18 MB 并不足以要求改成在线下载。

| HeaderActions／关于入口 | App 外链改为受控的系统浏览器入口 | 用户可返回，外部网页不会替换本地 App 页面 |
| 分享适配与观测卡片 | 生成当前观测内容并调用原生分享；临时文件可清理 | 单双日期准确，取消分享不报错，不申请相册读取权限 |
| 原生配置、隐私清单与资源 | 图标、启动画面、显示名、最低系统、权限、版本与 build number | Archive 校验与人工设备检查通过 |

生命周期采用官方 App 插件的 `appStateChange` 等事件；它在 iOS 对应原生应用失活／活跃通知。事件响应必须清除 `pendingPlay`，防止节气预计算完成后在后台启动；在取消异步监听及组件卸载时也处理迟到结果。[App 插件](https://capacitorjs.com/docs/apis/app)

轻量偏好使用 Preferences。官方提示移动系统可能清理 localStorage；该插件在 iOS 使用 UserDefaults，卸载后数据清除。使用时把 `PrivacyInfo.xcprivacy` 加入正确 target，并根据实际用途申报 UserDefaults 的必需原因；官方建议的对应理由是 CA92.1。[Preferences](https://capacitorjs.com/docs/apis/preferences)

安全区只指定一个负责层：原生 WebView inset 和 CSS safe-area 不能重复相加。建议以现有 `viewport-fit=cover` 与 CSS 统一控制为基础，在真实容器中确认。普通模式的顶部 padding 当前没有全面使用 safe-area，不能直接照搬手机浏览器截图。

音频首版建议遵循系统静音与中断行为，后台停止，不申请后台音乐能力。先做真机证据，再决定是否需要少量 AVAudioSession 适配；只有 HTMLAudio 无法达到已定义行为时才改用原生播放器。切到原生播放器也必须复用现有累计秒数模型，不能另起一条地图计时器。

外链可使用官方 Browser 插件，它在 iOS 使用 SFSafariViewController；系统分享使用 Share 插件。若图像分享依赖 Filesystem，还需按插件实际使用补充隐私原因声明。[Browser](https://capacitorjs.com/docs/apis/browser)、[Share](https://capacitorjs.com/docs/apis/share)、[Filesystem](https://capacitorjs.com/docs/apis/filesystem)

**7．地图性能与截图的专项处理**

当前主图开启了 `preserveDrawingBuffer: true`；代码扫描没有发现正式用户截图导出入口。应在真机上比较保留与关闭该设置的影响，并把未来分享的实现一起评估，不能为了优化直接删除后让图像分享出现黑图。

先记录单图、双图在相同设备和场景下的首屏时间、播放就绪时间、帧间隔、峰值内存、持续播放耗电与发热。不要同时升级 MapLibre 大版本；当前锁定版本是 5.24.0，迁移和渲染器升级分开处理。

如果高像素密度导致绘制过重，先调整 App 端渲染像素比／绘制频率并验证清晰度。现有播放按实际经过时间积分，可以在保持时间正确性的前提下评估较低绘制帧率；不能改成固定每帧加分钟。若分段预计算确实卡住交互，再考虑专用 Worker，保留最新请求生效和缓存上限。

WebGL 上下文丢失和 WKWebView 内容进程终止不是一件事。现有地图重试能处理前者；后者需要核查所选 Capacitor 版本的恢复机制，再决定是否补充原生处理。Apple 提供内容进程终止的代理通知。[WebKit 进程终止通知](https://developer.apple.com/documentation/webkit/wknavigationdelegate/webviewwebcontentprocessdidterminate(_:))

分享图像时，读取地图画布只能得到画布内容，不能自然包含 DOM 日期时间卡片。建议明确合成流程：取得已完成绘制的画布，再叠加日期、北京时间、图例和必要说明。双图分别合成；导出时固定观测时刻，清理临时文件，并验证分享图中的地图范围与实际成图要求。避免把“通用网页截图库可以截图”当作已验证结论。

**8．上架准备与本项目的具体问题**

Apple 审核 4.2 要求 App 提供超过重新包装网站的功能、内容与界面价值。因此提交时应清楚展示离线天文计算、节气跳转、双日对比、代表点太阳事件及观测分享。这个项目有可说明的独立工具价值，但不能保证只加容器或分享按钮就通过审核。[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)

建议在关于页提供模型与代表点说明、数据快照日期、资源许可、隐私政策、支持联系方式和版本信息。保留仓库入口，但 App 中放入关于页更能突出观测任务；这是待实施的界面建议，不是本次已修改行为。

隐私政策 URL 即使在不收集数据时也需要准备，App Store Connect 的隐私回答应覆盖最终全部代码和 SDK。现有本地计算、无账户无分析 SDK 的结构有利于申报“不收集数据”，但须对最终原生插件和网络行为核实后再填写。原生隐私清单与商店隐私标签是不同材料。[Apple 隐私填写说明](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/)

地图与音乐的使用、公开分发授权已在仓库中由维护者确认，不重复要求确认该事实。上架阶段整理已有凭证，并核对其是否覆盖拟定的 App 分发、商业用途和发布地区；第三方素材仍不改授 MIT。

如果面向中国大陆发布，提前核实两个相互独立的事项：

- APP 备案适用性：工信部通知针对在境内从事互联网信息服务的 APP；Apple 也说明中国大陆部分 App 需要有效 ICP 备案信息。应按最终功能和发行主体向有关平台／主管渠道核实，不能推断所有离线 App 都必须备案，也不能因为离线就保证豁免。网站备案不应直接当作 App 备案材料。[工信部通知](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html)、[Apple 中国大陆可用性说明](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information)
- 地图成图与审核：《地图管理条例》涉及向社会公开地图的审核与疆域完整表达，数据使用许可不能替代成图审核结论。本项目手机隐藏南海附图，而主图分离部分南海几何，须把手机、横屏、双图和分享图作为实际样品核查。应向自然资源主管部门或具相应能力的地图服务机构确认适用办理路径，不能借用来源页面审图号，也不能认定底层保留完整数据就等于屏幕成图已满足要求。[《地图管理条例》第九、十五、二十二条等](https://xzfg.moj.gov.cn/front/law/detail?LawID=421&Query=)

这些事项按发布场景处理，不妨碍先做本地技术样机；如后续确需调整手机地图表达，应形成独立的已确认规格，不在本次调研中擅改地图。

**9．开发与分发流程**

先在 Mac 安装／选择完整 Xcode 和 iOS 模拟器，准备一台可连接的 iPhone。使用自己的 Apple 账户与 Team 管理签名，不把账号密码、证书私钥或签名文件写入仓库。Bundle ID 在最终发布主体的账户下核验后固定，文档中的示例不能直接视为已注册标识。

接入流程的命令示意如下；本次没有执行安装或修改依赖：

```sh
npm install --save-exact @capacitor/core@8 @capacitor/ios@8
npm install --save-dev --save-exact @capacitor/cli@8
npx cap init
npm run build
# 实施准备脚本后，生成 dist-ios，并把 webDir 指向该目录
npx cap add ios
npx cap sync ios
npx cap open ios
```

安装时核对 core／cli／ios 的实际解析版本一致，插件选择同一代兼容版本并锁定。按阶段安装 App、Preferences、Status Bar、Browser、Share 等真正使用的插件，避免先装一组未使用原生能力。

后续开发固定为“测试 → Web 构建 → 准备 App 资源 → cap sync → Xcode 运行／Archive”。网站更新不会自动更新用户已安装 App；首版统一通过 App Store 版本更新，暂不引入远程代码热更新。Apple 对下载执行改变功能的代码有明确约束。[审核软件要求](https://developer.apple.com/app-store/review/guidelines/)

分发方式取决于真实目标：

| 目标 | 方式 | 特点 |
| --- | --- | --- |
| 先在自己 iPhone 验证 | Xcode 开发安装 | 免费 Apple 账户可做个人设备测试，但 Personal Team 描述文件 7 天到期，需重新配置／安装 |
| 邀请朋友试用 | TestFlight 外部测试 | 需要正式开发者计划；首个外部测试构建需审核，构建最多测试 90 天 |
| 长期面向公众使用 | App Store | 需要签名、商店资料、测试、审核及对应地区材料 |

Apple Developer Program 标准费用为每年 99 美元或当地货币，以注册地区显示为准。个人注册的 App 按个人姓名列示；组织注册按法律实体名称列示，组织通常需要 D-U-N-S 信息。由于公开名称归属由实际发布主体决定，不代替维护者选择身份。[会员比较](https://developer.apple.com/support/compare-memberships/)

TestFlight 官方允许最多 100 名内部测试成员、10,000 名外部测试者，但本项目先邀请少量明确设备型号的测试者更便于定位问题。90 天限制意味着它是测试渠道，不是永久分发替代品。[TestFlight 概览](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/)

最终提交流程为注册 App 记录和 Bundle ID、配置 Team 与自动签名、设置版本／build number、Archive、验证并上传、TestFlight、准备描述／图标／截图／支持与隐私 URL／年龄分级／出口合规回答、提供审核演示步骤、选择销售地区，审核通过后手动发布。出口合规按最终依赖和实际加密使用回答，不预先复制其他 App 的答案。

**10．阶段计划、时间与停止条件**

以下是熟悉 Vue 与基本 iOS 工具链的开发者的初步工作量估算，非交付承诺；不含账号审核、外部备案／地图材料处理和 Apple 审核等待。

| 阶段 | 工作 | 产出与进入下一阶段条件 | 估算 |
| --- | --- | --- | --- |
| A：环境与发行准备 | Xcode、设备、账户身份；同步核实发行材料 | 能启动最小原生工程，明确后续发布路径 | 0.5–1 天 |
| B：真机技术样机 | Capacitor、本地资源、单／双图、音乐、后台暂停 | 飞行模式首次启动可用；无持续白屏、致命内存／渲染问题 | 1–2 天 |
| C：平台适配 | 安全区、状态栏、生命周期、偏好、外链、恢复 | 核心操作与网页规则一致，真机旋转／中断可靠 | 2–4 天 |
| D：产品收尾 | 图标、启动画面、关于与说明、观测分享 | 内容完整、图像导出可靠、权限精简 | 2–3 天 |
| E：验收和交付 | Web 回归、iPhone／iPad、性能、TestFlight、商店资料 | 可复核测试记录、可安装构建和审核资料 | 2–4 天 |

本地可体验样机约 1–3 个工作日；达到较完整首版约 8–15 个工作日，可按 2–3 周工程量规划，首次使用 Xcode、设备不足或发生兼容问题时另加余量。公开上架日期必须把外部办理和审核单独计算。

阶段 B 是关键决策点：先证实本地资源、地图 GPU 与音乐在真实 iPhone 可行，再投入完整发布。若失败，先判断具体瓶颈，尝试局部像素比／Worker／音频／生命周期修复；只有核心性能或系统能力经测量确实不达标，才重新评估原生重写。

**11．验收用例与可测目标**

建议以下内容作为实现阶段的验收清单，而非本次已经通过的结果：

- 完成安装后，首次启动即切断网络，地图、日历异步模块、24 节气、双日对比、详情和音乐均可用；外链离线失败不影响观测。
- 真正冷启动仍为北京时间今天／00:00／暂停；跨年更新范围；设备切到其他时区不改变北京时间语义。
- 滑块、日期、节气和 24:00 重播保持原有规则；双图依旧一条时间轴、一份音频。
- 锁屏、切 App、控制中心、来电／系统音频中断及分享面板关闭后不会意外继续播放；无后台音乐遗留。
- 静音开关、扬声器、耳机、蓝牙切换及首次媒体加载均有真机检查，音乐 seek 与累计秒数模型一致。
- 竖屏／横屏、单图／双图、亮／暗色、沉浸／普通模式、iPad 不同窗口尺寸下，标签和按钮可读可点；地区详情与日历不被安全区挡住。
- VoiceOver 能通过可访问的地区选择入口完成地图选择与详情阅读；Canvas 中可点击的省名不等于屏幕阅读器天然可访问，必要时补充 34 省列表作为等价入口。验证系统字体放大与减少动态效果。
- 图形上下文丢失、内容进程退出、连续切换日期与单双图后，有明确恢复结果；恢复不触发多个播放循环或重复音频。
- 分享卡片与当前日期、分钟及地区一致，包含必要地图表示和模型说明；取消分享、保存失败及临时文件清理不影响主页面。
- Web 原有 `/atlas/` 相对路径部署、桌面与手机浏览器仍通过相应回归；没有把平台专用代码变成 Web 必须依赖的原生能力。

性能目标先作为阶段 B 的暂定门槛：在约定的最低档参考真机上，连续 5 次冷启动记录地图可见与播放就绪的中位数及最慢值；争取地图可见 2 秒内、播放就绪 3 秒内，超出时根据实际瓶颈调整。正常播放以稳定 30 fps 以上为基线、60 fps 为争取目标；用帧时间分布与掉帧记录评估，不能只看平均数。连续使用 10 分钟及反复切换后无崩溃、无持续内存增长，暂停后无应用自有连续绘制循环。

这些数字是拟定工程目标，不是当前实测结果或普遍硬件保证。设备型号、系统、温度与测试场景要记录在报告中。至少覆盖最低支持系统设备、小屏设备、当前系统 iPhone，以及计划支持的 iPad；模拟器与 Playwright 只补充覆盖，不替代真机。

**12．现在应做的第一步**

先完成 Capacitor 真机技术样机，验证离线、地图、双图、音频与前后台；同时按实际发行目标准备账号和地图相关资料。该顺序能够尽早验证最大技术不确定性，也避免等成品写完才发现发行路径不成立。
