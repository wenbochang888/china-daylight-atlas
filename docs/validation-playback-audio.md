本轮命令：`npm run typecheck`、`npm run test:unit`、`npm run test:e2e`、`npm run build`、`node scripts/static-check.mjs --audio`；加强后的网络恢复用例使用 `npm run test:e2e -- tests/e2e/audio.spec.ts --grep '音乐请求失败'`。浏览器及本地服务检查需本轮环境的沙箱网络权限，获准后完成。

## 已覆盖行为

- 初始页面不发起 MP3 请求，播放按钮启动唯一隐藏音频；暂停及时间轴操作保留音乐进度，再次播放继续。
- 音乐曲尾附近自然回到开头，地图分钟继续推进，音乐播放速率始终为 1。
- 实际换日归零；节气启动时从头播放；开启和退出双图都暂停并保留进度，没有重复音频。
- 后台暂停后回来不自动恢复；日终停止，点击重播时地图与音乐同时从头开始。
- 网络失败及 `NotAllowedError` 注入均不停止地图；暂停时重试按钮禁用，用户点击重试可恢复音乐并清除提示。
- 单元测试覆盖同步异常、未加载元数据时的重置、旧请求成功不暂停新播放、迟到拒绝不覆盖新错误、媒体错误不被旧成功清除、卸载释放监听与媒体资源。

审查后的提交说明草稿：`feat: 昼夜播放联动循环钢琴音频并支持失败重试`。仅提供草稿，本目录没有 Git 仓库。

## 验证边界

自动测试检查真实 MP3 的加载、解码、时长、媒体播放状态、进度、循环及暂停。将媒体进度移至曲尾附近后验证原生循环，没有等待完整 4 分 25 秒；后台场景注入 visibilitychange 和 document.hidden。测试均为桌面浏览器及手机尺寸／触控模拟，没有实际监听设备扬声器，尚未在真实 iPhone／Android 上验证声音、系统静音或耳机行为。
