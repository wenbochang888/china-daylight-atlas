## 启动测量

在同一台机器上分别测旧版与新版，使用相同本机静态服务规则：哈希资源长期缓存，HTML／普通JSON检查更新，gzip，Chromium headless，1440×1000，10 Mbps、60 ms延迟、4倍CPU减速。每版3次独立浏览器上下文，每次先冷导航、再同上下文暖导航，表格取中位数。基线从提交 `58f39756a686987db1902e43fe25cd69f0dc4a40` 的临时快照构建，保留同期工作区已有入口图标改动。

| 指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 首屏地图数据原始大小 | 3,321,234 B | 1,725,452 B |
| 地图数据gzip大小 | 833,221 B（5个文件合计） | 597,612 B（数据包） |
| 地图JSON请求数 | 5 | 0 |
| 记录的首屏资源请求数 | 8 | 4 |
| 冷缓存地图显示 | 2,665 ms | 2,318 ms |
| 冷缓存播放就绪 | 2,665 ms | 2,663 ms |
| 暖缓存地图显示 | 1,601 ms | 1,389 ms |
| 暖缓存播放就绪 | 1,601 ms | 1,735 ms |
| 冷缓存记录的传输量 | 1,284,130 B | 1,047,973 B |
| 暖缓存记录的传输量 | 1,800 B | 300 B |

原始地图数据减少约48.0%，gzip地图数据减少约28.3%；测量中冷／暖地图显示分别提前约13.0%／13.2%，记录的冷缓存传输量减少约18.4%。地图显示后再准备播放，测量中约需额外0.35秒；暖缓存播放就绪比旧版晚约0.13秒。这项变化优先让地图出现，不能表述为所有启动指标均变快。

地图显示指标是在主附图就绪并出现时间卡片时记录，播放指标是按钮解除禁用。传输量来自浏览器 Resource Timing 与导航记录，包含响应头估算，不是服务器全连接字节计数；资源请求数不包含HTML、blob worker及浏览器独立图标请求。小样本模拟只用于同条件比较，不代表真实手机、线上带宽或保证秒开。

命令：`node scripts/startup-check.mjs --label=baseline --root=<旧版生产目录>`、`node scripts/startup-check.mjs`。完整样本见 [基线](validation-images/startup-music/baseline.json) 与 [优化后](validation-images/startup-music/optimized.json)。
